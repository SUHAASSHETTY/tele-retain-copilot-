# Model / system card: Customer Service & Retention Copilot

## System summary
A LangGraph multi-agent copilot for telecom customer care (`src/graph.py::build_graph`). A supervisor
routes each contact through workers:

- intent classification: `src/agents/intent_agent.py::intent_agent`
- account lookup over MCP: `src/agents/account_agent.py::account_agent`
- agentic policy retrieval: `src/agents/policy_retrieval_agent.py::policy_retrieval_agent`
- retention offers: `src/agents/retention_offer_agent.py::retention_offer_agent`
- resolution drafting: `src/agents/resolution_agent.py::resolution_agent`

Input and output guardrails are the first and last nodes. Offers above the approval threshold stop at a
human approval interrupt (`src/agents/human_loop.py::human_approval`).

## Models

| Component | Model | Where configured | Notes |
|---|---|---|---|
| Agent LLM (intent, routing, drafting, RAG grading, memory extraction, summaries) | Google Gemini, default `gemini-3.8-flash` | `src/config.py::load_settings` (`GEMINI_MODEL`), client in `src/llm.py::get_chat_model` | `gemini-2.5-flash` returns 404 for new users and is not used. Temperature 0. Shared rate limiter `src/llm.py::RATE_LIMITER`. |
| Eval judge | Google Gemini via DeepEval `GeminiModel` (`GEMINI_JUDGE_MODEL`) | `scripts/run_eval.py::CachedGeminiJudge` | Only Gemini is allowed: `tests/test_provider_policy.py::test_eval_judge_is_gemini` |
| Embeddings | `sentence-transformers/all-MiniLM-L6-v2` (local) | `src/tools/rag_tool.py::embed` | Policy retrieval and long-term memory search |
| PII detection | Presidio + spaCy `en_core_web_sm` (local) + custom recognizers | `src/guardrails/pii.py::presidio_analyzer` | Output guard and masking |
| Deterministic fallback | Rules / templates | `src/agents/intent_agent.py::classify_rules`, `src/agents/resolution_agent.py::template_message`, `src/tools/rag_tool.py::HeuristicJudge` | Used when Gemini is unavailable or disabled; every use is labelled in the engine log |

**Important: which engine produced the committed evidence.** All committed evidence (sample runs, traces,
eval, red team) was generated in deterministic mode, with no Gemini calls. The configured model was unusable
for the development key: 404 on `gemini-2.5-flash`, and free-tier quota of 20 requests/day/model on
`gemini-3.8-flash` (see `docs/failure-analysis.md` F5). The reported quality numbers therefore describe the
rules/templates engine plus the deterministic controls, not Gemini's language quality.

## Data
- **Synthetic only.** Customers, accounts, invoices, complaints, plans, retention offers and the 11-document
  policy corpus are generated deterministically (seed 17) by `scripts/generate_synthetic_data.py` into
  `data/synthetic/telecom.db` and `data/policy_corpus/`.
- Phones use the reserved 555-01xx range, emails use `example.com`, and customer IDs look like `CUST-######`.
- No real personal data is used, and no model was trained or fine-tuned.
- Evaluation data: `data/golden_set.jsonl` (18 cases) and `data/redteam_set.jsonl` (14 attacks), from the same generator.

## Intended use and users
- **Primary users:** telecom care agents, who get a drafted resolution with policy citations for a customer
  contact (billing questions, plan changes, complaints, cancellations and retention).
- **Approvers:** retention team leads approve or reject offers above `src/policy_limits.py::APPROVAL_THRESHOLD`
  through the approval interrupt.
- **Customers** (chat mode, `src/cli.py::cmd_chat`) are told they are talking to an AI assistant and can ask
  for a human (`src/cli.py::AI_DISCLOSURE`).
- Decision boundaries are rule-based, not model-based: outcomes come from `src/agents/resolution_agent.py::decide_outcome`,
  and offer limits from `mcp_server/server.py::evaluate_offer`.

|---|---|---|
| Intent accuracy | 1.0 (16 cases with an expected intent) | 0.938 before the F1 fix |
| Action accuracy | 1.0 | 0.944 before the F1 fix |
| Policy-ref recall | 1.0 | Expected clauses cited in the reply |
| Citation validity | 1.0 | Every cited clause exists in the corpus |
| Hallucination (DeepEval, Gemini judge `gemini-3.6-flash`) | **partial: 2 of 18 cases judged, both pass (score 1.0)** | 16 judge calls failed on free-tier 503/429 and are recorded as errors (F5); indicative only |
| Faithfulness / answer relevancy (DeepEval, Gemini judge) | **not run** | Free-tier quota (F5); no scores are reported |

- **Red team:** `reports/redteam_results.json`. 14 attacks, 0 harmful outcomes, detection 0.929,
  blocked where expected 1.0. RT-13 (asking for one's own identifiers) is undetected but cannot leak, because
  tools only return masked identifiers.
- **Latency and cost:** `reports/golden_signals.json`. Warm end-to-end p50 about 275 ms and tool p50 about 19 ms in
  deterministic mode. Token cost is not yet measured because no Gemini calls were traced.

Caveat: the golden set is small and was written by the same team that built the rules. The deterministic
accuracy numbers show the controls behave as specified; they are not evidence of general language
understanding.

## Known failure modes
See `docs/failure-analysis.md`:
- [F1: service-quality complaints misread as ambiguous](failure-analysis.md#f1-service-quality-complaint-misclassified-as-ambiguous).
  The rule-based intent classifier covers the vocabulary it was given; new phrasings can still land in `clarify`.
- [F2: paraphrased prompt injection not detected](failure-analysis.md#f2-paraphrased-prompt-injection-not-detected).
  Injection detection is pattern-based; novel paraphrases can pass the input guard (harm is contained by the
  policy check and approval gate).
- [F3: cold-start latency](failure-analysis.md#f3-13-second-cold-start-on-the-first-turn-of-every-process).
  Fixed with warm-up; a process that skips `src/warmup.py::warm_up` pays about 13 s on its first contact.
- [F4: plaintext identifier in a pipeline log](failure-analysis.md#f4-plaintext-customer-id-written-under-logs).
  Fixed; guarded by `scripts/check_pii_leaks.py` on every regeneration.
- [F5: LLM-as-judge metrics unavailable](failure-analysis.md#f5-llm-as-judge-metrics-not-produced-open-partially-mitigated) (open, partial).

## Limitations
- Caller authentication is simulated: the contact's customer ID stands in for an upstream login.
- The retention "churn risk" score is a hand-written formula over synthetic features
  (`scripts/generate_synthetic_data.py::churn_risk`), not a trained or validated model.
- Semantic memory recall uses a small local embedding model. Scores are low, so recall of a stored fact
  relies partly on the "refers back" rule (`src/context/select.py::select_memories`).
- English only; no voice channel; no real billing or CRM integration.
- Automated approvals in reproducible runs are scripted stand-ins (recorded as `system:` actors), not people.

## Out-of-scope uses
- Any use with real customer data before a DPIA, consent and notice flow, and a security review
  (see `docs/compliance.md`).
- Autonomous granting of credits, discounts or fee waivers without the human approval gate.
- Credit decisions, collections, fraud adjudication, or any decision with legal or similarly significant
  effect on a person. Fraud-flagged accounts are escalated, never decided.
- Advice outside the customer's telecom account. Such requests are declined (POL-GOV-001 §2.1).
