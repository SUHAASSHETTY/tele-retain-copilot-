# Project: Customer Service & Retention Copilot (BC-AAIE-HACK-17, Telecom)

## What this is
A LangGraph multi-agent copilot for telecom customer care that classifies a contact's intent,
pulls synthetic account/plan data, retrieves offer/retention policy (agentic RAG), drafts a
resolution (resolve / offer / escalate), and routes discounts/credits above a threshold to a
human approval gate. It is instrumented with Arize Phoenix, cost/latency governed, guarded,
audited, documented for governance, and evaluated with DeepEval + pytest.

Scoring is AUTOMATED from committed repository evidence only. No live demo.

## Non-negotiable rules (violating any = lost marks)
1. EVIDENCE-IN-REPO: every claim must be backed by a committed artifact. Every evidence artifact
   (trace, log, report, csv, png) MUST be produced by committed code. Never hand-write or
   fabricate a log line, span id, metric, or eval score. If something can't be generated, say so.
2. CITATION-RESOLVES: any doc that cites a run_id / span_id / log record / file path must point
   to something that actually exists in the committed repo. `scripts/verify_citations.py` enforces this.
3. SYNTHETIC DATA ONLY: all customers, accounts, plans, billing and policies are generated by
   `scripts/generate_synthetic_data.py`. Customer IDs, account numbers, phone, email, billing
   amounts tied to a person are MASKED wherever shown and NEVER written to any log in plaintext.
4. GEMINI ONLY: the application's only LLM provider is Google Gemini (langchain-google-genai,
   and DeepEval judge = Gemini). No OpenAI/Anthropic SDKs in requirements or code.
   Embeddings are local Sentence-Transformers (all-MiniLM-L6-v2).
5. PIP + PYTHON ONLY: Python 3.11+, no Docker, no external DB service. SQLite files + local
   Chroma/FAISS + in-process Phoenix.
6. REPRODUCIBLE: `python -m src.cli run --input data/sample_contacts.jsonl` runs the copilot;
   `python scripts/regenerate_evidence.py` regenerates traces, logs, eval, golden signals,
   dashboard. Both documented in README.
7. NO SECRETS: config via env vars + python-dotenv. `.env.example` committed, `.env` in .gitignore.

## Engineering conventions
- Async everywhere tools/models are called (ainvoke, async MCP client). Every external call has
  a timeout (asyncio.wait_for), tenacity retries with backoff, and a graceful fallback
  (escalate to human with reason) instead of crashing.
- Pydantic models for every node's structured output and every tool's input/output.
- A single `run_id` (uuid) per contact, propagated into Phoenix span attributes/metadata,
  tool_calls.jsonl, agent_actions.jsonl so everything cross-references.
- Masking helper `src/guardrails/pii.py::mask()` is the ONLY way PII reaches logs.
- Gemini free-tier rate limits: keep golden set small (~15–20 cases), add simple on-disk
  response caching for eval reruns, and back off on 429.
- Tests that check graph logic (routing, loops, contracts) must NOT need a live API key —
  use fake LLMs/stubs. Only eval + evidence regeneration hit Gemini.
- Commit after each phase with a clear message. Never commit .env, venv, caches, chroma temp dirs
  (but DO commit the evidence artifacts under traces/, logs/, reports/).
- Before claiming a phase is done: run it, show the output, and check the artifact exists.
